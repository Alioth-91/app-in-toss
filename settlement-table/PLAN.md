# 정산표 계획

## 7일 일정

이번 일정은 기능을 먼저 쌓고 마지막에 디자인을 덧씌우는 순서가 아니다. 각 화면의 목적과 상태를 먼저 정한 뒤, 그 화면에 필요한 도메인 규칙과 앱인토스 연동을 연결한다. 화면 작업은 320px·390px·키보드·safe area를 함께 확인하고, 큰 작업은 여러 승인 단위로 나눈다.

### Day 1 — 정산 규칙·화면 경계·디자인 기준 고정 (완료)

1. [x] `calculateSettlement`와 `buildTransfers`를 복구하고 정산 규칙 테스트를 만든다.
2. [x] `App`의 화면 전환과 `SettlementFormProvider`의 입력 상태 경계를 정리한다.
3. [x] 홈·모임 설정·지출 화면의 기본 역할을 나누고, 도메인 계산과 화면 코드를 분리한다.

완료 조건: 정산 계산과 송금 방향이 테스트로 고정되고, 홈에서 설정·지출 화면으로 이동해도 입력 상태가 사라지지 않는다.

### Day 2 — 홈·모임·참여자 설정 디자인 (완료)

1. [x] 홈의 서비스 설명, 새 정산 CTA, 저장 내역 없음 상태, safe area 여백을 구현한다.
2. [x] 모임 이름, 진행 단계, 참여자 행, 인원 제한, 빈 이름·중복 이름 오류, 하단 고정 CTA를 구현한다.
3. [x] 입력 내용 초기화 확인 UI와 뒤로 가기 시 입력 상태 유지를 연결한다.
4. [x] 320px·390px 브라우저 흐름과 참여자 추가·삭제를 확인한다.
5. [x] 여러 화면에서 반복되는 색상·간격·모서리·타이포그래피를 CSS 변수로 정리한다.

완료 조건: 사용자가 홈에서 정산을 시작해 모임 이름과 참여자를 입력하고, 오류를 이해한 뒤 다음 단계로 이동할 수 있다.

### Day 3 — 지출 관리 기본 화면과 TDS 바텀시트 (완료)

1. [x] 지출 화면에 진행 단계, 모임 요약, 총액, 지출 없음 상태, 지출 추가 CTA를 배치한다.
2. [x] Toss TDS `BottomSheet`를 지출 추가 흐름에 연결한다. 시트의 닫기·바깥 영역·뒤로 가기와 하단 저장 CTA를 확인한다.
3. [x] 기존 `react-hook-form` 검증을 TDS 하단 CTA의 제출과 연결해, 저장 전에 금액·결제자·참여자 검증이 실행되게 한다.
       완료 조건: 지출 추가 시트가 320px·390px에서 열리고 닫히며, 저장 성공 시 총액과 목록 상태가 즉시 바뀐다.

### Day 4 — TDS 입력·선택 UI와 지출 동작 완성

1. 설치된 TDS API를 기준으로 금액 입력은 `TextField`, 결제자·참여자 선택은 `Chip` 계열로 바꿀지 확인하고 적용한다.
2. 금액 입력 오류와 참여자 선택 상태가 시트 안에서 이해하기 쉽게 보이는지 확인한다.
3. 지출 목록 카드의 결제자·금액·참여자를 디자인에 맞게 표시하고, 긴 이름과 많은 참여자도 무너지지 않게 한다.
4. 같은 입력 시트를 재사용해 지출 수정과 삭제를 연결한다. 수정 취소 시 기존 값이 유지되게 한다.
5. 첫 지출 이후 참여자 추가·삭제 제한을 도메인 규칙과 화면 오류로 연결한다.
6. 지출이 없을 때는 `정산 결과 보기`를 막고, 지출이 있으면 결과 화면으로 이동시킨다.

완료 조건: 지출을 추가·수정·삭제한 뒤 화면의 총액과 참여자 부담 상태가 맞고, 유효한 지출이 있을 때만 결과로 이동한다.

### Day 5 — 정산 결과와 공유 화면

1. `calculateSettlement` 결과를 결과 화면에 연결해 전체 금액, 사람별 결제액·부담액·차액을 표시한다.
2. 송금 목록은 받는 사람과 보내는 사람을 읽는 순서로 보여주고, 송금할 필요가 없는 상태도 별도로 안내한다.
3. 긴 이름·긴 송금 목록·금액 0원 같은 결과 상태를 디자인에 맞게 처리한다.
4. 공유 문구를 순수 함수로 만들고 테스트한 뒤, `src/lib`의 `ShareGateway` 뒤에 브라우저와 앱인토스 동작을 둔다.

완료 조건: 결과 화면의 금액과 송금 방향이 계산 결과와 일치하고, 공유 버튼이 같은 정산 내용을 복사·공유한다.

### Day 6 — 저장·홈 내역·재편집

1. 원본 입력을 저장하고 결과는 다시 계산하는 저장 모델과 버전 필드를 확정한다.
2. 저장소 어댑터와 손상 데이터 오류 상태를 만든다. 브라우저 저장소와 도메인 계산을 직접 섞지 않는다.
3. 홈에 저장 내역 카드·빈 상태·최근 항목을 디자인하고, 저장된 정산표를 다시 연다.
4. 모임 이름·참여자·지출을 수정해 기존 기록을 갱신하고, 단일 삭제·전체 삭제·취소를 연결한다.
5. 저장 후 새로고침, 수정 후 재계산, 삭제 후 빈 상태를 확인한다.

완료 조건: 저장된 원본이 새로고침 뒤 복원되고, 다시 계산한 결과가 유지되며, 삭제 확인에서 취소하면 데이터가 사라지지 않는다.

### Day 7 — 보상형 광고·전체 회귀·문서 마무리

1. 설치된 SDK 타입과 공식 문서를 기준으로 보상형 광고 브리지를 확인하고 `src/lib` 어댑터로 감싼다.
2. 세 번째 저장부터 광고를 요구하는 정책을 순수 함수로 분리한다. 브라우저에서는 fake gateway, 앱인토스에서는 실제 브리지를 사용한다.
3. 광고 준비·시청 성공·실패·취소 상태를 저장 흐름에 연결한다. 실패·취소 때 원본 입력은 보존한다.
4. 홈 → 설정 → 지출 → 결과 → 공유 → 저장 → 재진입 전체 흐름을 320px·390px, 긴 이름, 많은 지출, 키보드, safe area, 뒤로 가기, 새로고침 조건에서 점검한다.
5. `npm run test`, `npm run lint`, `npm run build`, `git diff --check`를 실행하고, 실기기에서만 확인할 항목을 문서에 남긴다.
6. 완료된 설계·구현·검증 결과와 알려진 제한을 문서에 반영한다.

완료 조건: 핵심 사용자 흐름에 막힘이 없고 자동 검증이 통과하며, 브라우저에서 확인할 수 없는 앱인토스·실기기 항목이 별도로 정리되어 있다.

## 일정 운영 원칙

- 하루의 항목을 한 번에 승인하지 않고, 독립적으로 검증 가능한 50~100줄 안팎의 단위로 나눕니다.
- 각 단위 전에는 범위·파일·성공 조건·검증 방법을 알리고 승인받습니다.
- 각 단위 후에는 해당 테스트와 lint를 실행하고, 하루 마지막에는 전체 test·lint·build를 실행합니다.
- 일정이 밀리면 시각적 장식의 추가 변형을 줄이고 계산·저장·광고 정책의 정확성을 우선합니다.
- 출시 제출과 앱인토스 심사 대응은 이 7일에 포함하지 않습니다.

## 승인된 의존성 기준

- React 18.3.1, React DOM 18.3.1
- `@apps-in-toss/web-framework` 3.0.5, `@apps-in-toss/devtools` 3.0.5
- `@toss/tds-mobile` 2.5.1, `@toss/tds-mobile-ait` 2.5.1
- `react-hook-form` 7.87.0
- Vite 8.2.2, TypeScript 6.0.3, Vitest 4.1.9
- ESLint 및 React 타입 패키지는 `package.json`의 고정 버전을 사용

## 범위 고정

- 참여자 2~10명, 원화, 지출별 균등 분할만 지원합니다.
- 저장 2개까지 무료, 세 번째부터 보상형 광고 완료 후 저장합니다.
- 저장 한도는 10개이며, 기존 내역 수정은 광고와 저장 개수 증가가 없습니다.
- 서버 저장·실시간 공동 입력·송금 실행·OCR·배너 광고·전면 광고는 포함하지 않습니다.

## UI 디자인 기준

- 화면 디자인 작업은 [`정산표 UIUX 디자인`](<../docs/정산표 UIUX.dc.html>)을 기준으로 진행합니다.
- 독립 화면은 홈·저장 내역, 모임·참여자 설정, 지출 관리, 정산 결과의 4개로 구성합니다.
- 빈 상태, 지출 추가·수정, 삭제 확인, 저장·광고 안내는 별도 화면이 아니라 각 화면의 상태·바텀시트·모달로 처리합니다.
- 디자인 시안은 시각적 계층과 인터랙션 기준으로 사용하며, 계산·검증·저장 정책은 승인된 제품 설계와 테스트를 우선합니다.

## 소스 구조

- `src/features/settlement/`: 정산 타입·계산·검증·저장 정책 같은 순수 제품 규칙
- `src/components/`: 여러 화면에서 재사용하는 UI
- `src/screens/`: 사용자 화면과 화면 단위 조합
- `src/hooks/`: React 상태·폼·화면 흐름
- `src/lib/`: 앱인토스 SDK·저장소·공유 어댑터
- `src/test/`: 기능별 테스트·공통 fake·비식별 fixture
